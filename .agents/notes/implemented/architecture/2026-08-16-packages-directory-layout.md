# Agent Note: Owned packages under packages/

Status: implemented

English | [中文](2026-08-16-packages-directory-layout.zh.md)

## Problem

The two owned npm packages sat at the repository root (`dsh-plugin-desktop/` and `dsh-plugin-desktop-connection/`), while the documentation tier taxonomy already names `packages/` as the home of shipped source and the standard pnpm monorepo convention keeps owned packages under a `packages/` directory; root-level package folders blurred the boundary between packages and ad-hoc repo folders.

## Decision

The two desktop packages live under `packages/`: `packages/dsh-plugin-desktop` and `packages/dsh-plugin-desktop-connection`. The root pnpm workspace lists both `packages/*` paths, and the `workspace:*` dependency from the desktop plugin to the connection plugin is unchanged because it resolves by package name, not path. Package names, row ids, the Cordis composition, and module-level `dsh-plugin-desktop/webserver` references are untouched. The boot tests' repository-root constant steps up through the added level (`new URL('../../../', import.meta.url)`); the unused `REPO_ROOT` in `electron/boot-desktop.js` was removed. `.gitignore`, `scripts/add-missing-deps.mjs`, the root `README.md`, root `AGENTS.md`, and `docs/architecture.md` name the `packages/` paths; `pnpm-lock.yaml` importer entries and the workspace `node_modules` symlinks are regenerated by `pnpm install`.

## Alternatives considered

**Keep the packages at the repository root.** Minimizes churn but leaves the layout against the documented tier taxonomy and the `packages/` convention, and gives future owned packages no obvious home.

**Move under `packages/` and rename the packages (scoped names).** Renaming would change every row id, patch guard name, import, and the composition contract for no functional gain; the move keeps package names stable so only paths change.

## Consequences

The layout matches the documented tier taxonomy and the standard monorepo convention, so future owned packages have an obvious home and docs/script paths name real directories. The cost: every path reference to the old root-level directories was updated in the same change, and any stale reference would point into the now-`packages/`-rooted tree; package names and the runtime composition are unchanged, so tests and rows differ only in the boot tests' repository-root path.
